# bmad-dev-workflow 决策日志

## 2026-06-04

- 创建 `bmad-dev-workflow` 作为 simple workflow skill，而不是 persona agent。原因：用户目标是串联既有 BMad 开发流程，不需要新的长期身份或记忆。
- 采用同一 session 内“软清理”方案，不使用 subagent。软清理不声称删除上下文 token，只通过 handoff 文件、30 行内阶段摘要、下一阶段最小字段读取来减少上下文污染。
- 不复制 `bmad-create-story`、`bmad-dev-story`、`bmad-code-review` 的内部流程。新 skill 只做编排、状态检查、handoff、循环策略，避免分叉后与上游 skill 行为漂移。
- 默认 `require_story_approval = true`。story 是后续开发的权威规格，生成后进入开发前保留人工确认。
- 默认 `auto_continue_review_fix_loop = false`。现有 `bmad-code-review` 存在人工 checkpoint 和 patch/decision 菜单，默认不自动进入修复循环。
- 增加 `review_policy = "interactive"`，明确当前版本不会绕过 `bmad-code-review` 的人工 checkpoint；该 skill 只预填 review 目标、story/spec、diff base。
- 默认 `auto_commit = true`，遵循当前项目 `AGENTS.md` 的提交规则；实际执行时仍必须只暂存当前任务相关文件，并运行必要验证。

## 2026-06-05

- 将 `bmad-dev-workflow` 的 review 阶段扩展为支持 `review_policy = "automatic"`。自动模式由父 workflow 传入明确的 story、diff base 和 spec context，不再要求用户确认 review target、checkpoint、patch 菜单或 next-step 菜单。
- 自动 review 不在 review 阶段直接修改业务代码；`patch` findings 写回 story 作为 action items，由既有 Review Follow-Up Loop 决定是否进入下一轮 `bmad-dev-story`。
- `decision-needed`、无法构造 diff、无法读取 story/spec、缺少外部 review 执行能力等仍保留 HALT，因为这些不是安全的自动默认值。

## 2026-06-09

- 将入口明确拆成 `ready-story` 与 `requirement-to-story` 两种模式。前者继续自动寻找或使用现有 `ready-for-dev` story；后者在没有 ready story 且用户提供描述性需求时，把原始输入作为 `story_creation_request` 交给 `bmad-create-story`。
- `requirement-to-story` 模式下，没有 backlog story 不再自动 HALT。阻塞条件收窄为需求无法形成单个可实现 story、缺少必要规划上下文且不能安全推断，或子 story 创建流程自身 HALT。
- handoff 增加 `workflow_mode` 和 `story_creation_request`，保证软清理后仍能追溯 story 创建来源。
