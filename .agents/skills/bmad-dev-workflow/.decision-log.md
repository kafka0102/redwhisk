# bmad-dev-workflow 决策日志

## 2026-06-04

- 创建 `bmad-dev-workflow` 作为 simple workflow skill，而不是 persona agent。原因：用户目标是串联既有 BMad 开发流程，不需要新的长期身份或记忆。
- 采用同一 session 内“软清理”方案，不使用 subagent。软清理不声称删除上下文 token，只通过 handoff 文件、30 行内阶段摘要、下一阶段最小字段读取来减少上下文污染。
- 不复制 `bmad-create-story`、`bmad-dev-story`、`bmad-code-review` 的内部流程。新 skill 只做编排、状态检查、handoff、循环策略，避免分叉后与上游 skill 行为漂移。
- 默认 `require_story_approval = true`。story 是后续开发的权威规格，生成后进入开发前保留人工确认。
- 默认 `auto_continue_review_fix_loop = false`。现有 `bmad-code-review` 存在人工 checkpoint 和 patch/decision 菜单，默认不自动进入修复循环。
- 增加 `review_policy = "interactive"`，明确当前版本不会绕过 `bmad-code-review` 的人工 checkpoint；该 skill 只预填 review 目标、story/spec、diff base。
- 默认 `auto_commit = true`，遵循当前项目 `AGENTS.md` 的提交规则；实际执行时仍必须只暂存当前任务相关文件，并运行必要验证。
