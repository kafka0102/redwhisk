# 领域文档

工程技能在探索代码库时，应按本文件消费领域文档。

## 探索前读取

- 根目录的 `CONTEXT.md`。
- 与当前改动相关的 `docs/adr/` 决策记录。

上述文件不存在时静默继续，不提示缺失，也不主动创建。仅当领域术语或决策确实需要沉淀时，再由相应技能创建。

## 文件布局

本仓库使用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用领域词汇

Issue 标题、重构建议、假设与测试名称中的领域概念，应使用 `CONTEXT.md` 定义的术语，避免采用已被词汇表排除的同义词。

所需概念未出现在词汇表中时，应重新确认项目现有用语；若确有缺口，记录给领域建模流程处理。

## 标记 ADR 冲突

输出与已有 ADR 决策冲突时，必须显式说明冲突，而不能静默覆盖。例如：

> 与 ADR-0007 冲突，但值得重新评估的原因是……
