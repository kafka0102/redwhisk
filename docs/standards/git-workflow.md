# Git 工作流规范

## 目标

本文档定义本仓库统一的 Git 提交流程与提交信息约束，适用于人工提交、AI 自动提交以及 delegation 场景下的子 Agent 提交。

正式规范优先级高于口头习惯、历史示例或外部 skill。外部 skill 仅作为执行提示，不替代本文。

## 适用范围

适用于以下操作：

- 创建本地 commit
- 编写 commit message
- 选择提交范围与分支边界
- 在 Agent / 子 Agent 场景下执行自动提交

不自动授权以下操作：

- `git push`
- `git merge`
- `git rebase`
- `git tag`
- 改写历史（如 `commit --amend`、强推、reset）

以上操作仅在用户明确要求时执行。

## 核心原则

### 1. 提交范围最小化

必须遵守：

- 一个 commit 只包含当前任务直接相关的文件
- 不得把无关格式化、顺手修复、脚手架噪音混入同一提交
- 仓库中存在其他未提交改动时，只能 stage 与当前任务直接相关的文件
- 若本次执行过 `pnpm format`、`cargo fmt` 或其他自动格式化命令，提交前必须检查一次工作区，确认这些命令是否改动了额外文件
- 自动格式化带出的额外文件若属于当前任务范围，应与本次任务一起提交；若不属于当前任务范围，必须在提交前回退，不能把它们遗留为未提交改动

禁止：

- 用一次“大而全”提交掩盖多个独立变更
- 把用户已有但与当前任务无关的改动一起提交

### 2. 先验证再提交

必须遵守：

- 提交前至少完成与本次改动直接相关的最小验证
- 若修改了文档，至少检查路径、索引、引用关系
- 若修改了代码，至少运行与改动直接相关的格式化与校验
- 完成验证后、实际 `git add` 前，必须再执行一次 `git status --short` 或等价检查，确认没有遗漏由格式化或验证命令带出的任务相关文件
- 若因环境限制无法验证，最终说明中必须明确写出未执行项与原因

### 3. 默认停留在当前分支

必须遵守：

- 默认在用户当前分支上完成本次提交
- 未经用户要求，不创建、不切换、不删除分支

说明：

- 本仓库的 AI 协作场景以“当前工作分支上的小步提交”为默认模式
- 外部 skill 中更完整的分支模型可作为背景知识，但不自动改变当前仓库操作策略

### 4. 中文 Conventional Commits

提交标题格式必须为：

```text
<type>: <简要描述>
```

约束如下：

- `type` 使用英文小写：`feat`、`fix`、`docs`、`refactor`、`test`、`chore`、`style`、`perf`、`build`、`ci`、`revert`
- `描述` 使用简体中文，聚焦“做了什么”，避免空泛表述
- 禁止使用 scope，即不要写 `type(scope):`，统一为 `type:`；模块/范围信息应体现在描述中

好的例子：

```text
docs: 补充项目级 Git 提交约束
fix: 修复任务详情页状态回填错误
chore: 调整本地开发脚本参数
```

不好的例子：

```text
update code
fix: 修复问题
修改了一些东西
fix(todo): 修复详情页状态回填错误
```

### 5. 正文按需补充

以下情况建议补充 commit 正文：

- 需要说明修改原因
- 需要说明关键取舍
- 需要说明验证方式
- 需要关联需求、缺陷或文档

正文可用简体中文短句，不要求机械套模板，但要确保可读。

### 5.1 Issue 关联

当本次任务直接来自 GitHub/GitLab Issue 或 work item 时，必须在 commit 正文追加 trailer：

```text
Refs: #<issue-id>
```

必须遵守：

- `Refs: #<issue-id>` 单独成行，放在 commit 正文尾部
- 同一 issue 下的后续修补提交，仍然追加同一个 `Refs: #<issue-id>`
- 若用户没有再次明确 issue 编号，Agent 可优先从当前仓库本地 issue 上下文状态或最近相关 commit 的 trailer 推断；若仍存在歧义，再向用户确认

示例：

```text
fix: 修复详情页状态回填错误

补齐状态映射逻辑并更新空值兜底。

Refs: #12
```

### 6. Agent 提交附加要求

Agent 或子 Agent 自动提交时，必须额外遵守：

- 提交前先读取 `AGENTS.md`
- delegation 时，把上述路径显式传递给子 Agent
- 最终说明中写清本次验证是否完成、未完成项是什么
