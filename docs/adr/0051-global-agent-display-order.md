# ADR 0051：智能体显示顺序全应用一份，拖拽覆盖启用置末

## 状态

采纳（待执行）。

## 背景

设置页「智能体」把项目级与全局级 profile 合成一张表。ADR-0020 第 4 条把禁用行固定排到表尾，同组再按 id 升序。用户要在第一列用握柄直接拖拽改顺序，并且这份顺序要被「启动 Agent 会话」的选择列表沿用。

若顺序按项目各存一份，同一条全局 profile 在不同项目会排在不同位置，和「全局配置」的心智不一致。若只改设置页、选择列表仍按启用置末，用户拖完后在启动入口看不到自己排的顺序。

## 决定

1. **交互**：设置页表格第一列是六点握柄，拖整行换序。不提供上下按钮，也不提供序号输入。
2. **一份顺序**：全应用共用一份显示顺序。在任一项目里拖拽，其他项目的设置页与启动选择列表看到同一顺序。
3. **混排**：项目级与全局级 profile 按这份顺序穿插；禁用行可以出现在任意位置，浅灰行底保留。
4. **消费方**：设置页表格按该顺序渲染。「启动 Agent 会话」选择列表用同一顺序，并继续隐藏未启用项。
5. **取代 ADR-0020 第 4 条的排序口径**：启用状态只决定浅灰行底与选择列表隐藏，不再把禁用行排到表尾，也不再按 id 决定先后。ADR-0020 第 4 条里「本期后端不做启动校验」仍然有效。
6. **存量初始顺序**：尚未写入显示顺序的 profile，按升级前的展示规则排一次并保存：启用在前，同组按 id 升序。之后只随拖拽改变。
7. **新建与自动播种**：手动新建和启动时自动播种的 profile 追加到整张表末尾，排在已有行（含禁用行）之后。同一次播种按既有播种顺序依次追加。
8. **切换启用状态**：启用改为禁用，或禁用改回启用，行留在原位。只改变浅灰行底，以及该 profile 是否出现在启动选择列表中。
9. **松手即保存**：拖拽松手后立刻把整份顺序写入数据库。保存失败时，表格回到松手前的顺序，并在设置页显示错误。不另设「保存顺序」按钮。

## 后果

- 升级后的第一眼顺序与现在的表格一致，用户不拖拽就不会看到跳动。
- 新出现的 profile 总在当前最后一行，不会插进用户已经排好的中间位置。
- 禁用再启用不会把一行挪回「启用组」，用户排好的位置保持不变。
- 保存失败时界面与数据库保持同一份旧顺序，用户能立刻看到这次拖拽没有生效。

## 考虑过的替代方案

| 方案 | 未采纳原因 |
| --- | --- |
| 每个项目一份顺序 | 同一全局 profile 在不同项目位置不同，和全局配置心智冲突 |
| 握柄旁再加上下按钮，或改用序号输入 | 原型对比后选定纯握柄拖拽 |
| 只改设置页，选择列表维持启用置末 | 用户排好的顺序在启动入口不可见 |
