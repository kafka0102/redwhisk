# ADR 0061：删除远程 Issue 时可同步删除宿主 Issue

## 状态

采纳（已执行）。

## 背景

删除 Issue 的确认框目前只删除本地副本。远程 Issue 工作台的旧设计明确「远程 Issue 的删除只删本地副本，不删远端对象」。用户要求在这条确认框里，对 GitHub / GitLab 远程 Issue 增加默认勾选的同步删除，并且必须先删宿主、成功后再删本地。

宿主「找不到」（404）不能当成已经删掉。GitHub 对无权访问也常返回 404，这与「远端不可用」一致：删除和无权在界面上是同一种状态，不能靠一次 404 判定远端已删除。

## 决定

1. 待办编辑页和只读详情的删除确认框，对来源为远程且宿主是 GitHub 或 GitLab 的 Issue，提供「同步删除 GitHub Issue」或「同步删除 GitLab Issue」。每次打开默认勾选，不记住上次。本地 Issue 不提供。
2. 勾选时先删除宿主上的这条 Issue，成功后才执行现有本地删除。取消勾选只删除本地副本。
3. 宿主任何失败都不删除本地，并显示该错误。找不到（404）、无权、未登录、离线和命令失败都算失败。不因为 404 再弹一次确认，也不把 404 当成删除成功。
4. 这是删除宿主对象，不是关闭。Issue 完成写回里的关闭远端保持不变。
5. 同步对账仍不把一次 404 自动当成远端已删除。

## 后果

- 默认勾选会永久去掉宿主上的 Issue。误确认不能靠取消本地删除挽回。
- 宿主已删除、本地删除却失败时，再次勾选同步删除会因为 404 停住。此时取消勾选才能删掉本地副本。
- 旧设计「删除远程 Issue 只删本地副本」只对取消勾选的路径继续成立。

## 代码事实来源

- 当前只删本地：`IssueService::delete_issue`（`src-tauri/src/features/issue/service.rs`）、待办与只读确认框（`src/features/issues/issue-detail/issue-editable-page.tsx`、`issue-read-only-page.tsx`）
- 404 与无权同一状态：`CONTEXT.md`「远端不可用」
- 被收窄的旧设计：`docs/superpowers/specs/2026-10-31-remote-issue-and-pr-workbench-design.md`「远程 Issue 的删除只删本地副本，不删远端对象」

## 替代方案

- 404 视为远端已不存在并继续删本地：被拒绝。404 也可能是无权访问，会在宿主 Issue 仍在时删掉本地副本。
- 404 后再问一次是否仍删除本地：被拒绝。用户选择直接当失败，只删本地靠取消勾选。
- 默认同步关闭而不是删除：被拒绝。关闭远端已由 Issue 完成写回负责，这里要删除宿主对象。
- 默认不勾选：被拒绝。用户要求默认勾选。
