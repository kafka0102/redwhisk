# ADR 0019：工作区内容搜索采用代码侧栏 + 纯 Rust 同步搜索

## 状态

采纳。

## 背景

「代码」Activity 需要 VS Code 式按内容搜索。可选 Modal 全屏搜索、独立 Activity，或侧栏互斥面板；引擎可选系统 `rg`、捆绑二进制或进程内纯 Rust。还需决定后缀推荐缓存与结果返回形态。

## 决定

1. **入口与布局**：仅「代码」Activity；分支栏右侧按钮在「文件树」与「代码搜索侧栏」之间互斥切换，不使用 Modal。
2. **作用域**：仅当前选中代码根；默认忽略目录与文件树相同的 `HIDDEN_DIRS`，不叠加 `.gitignore`。
3. **引擎**：进程内纯 Rust 遍历与行匹配，不依赖本机 `rg`，避免分发与 PATH 差异。
4. **触发与契约**：回车发起一次同步 command；改匹配开关或包含/排除 tag 不自动重搜。结果有界（约 200 文件 / 文件 50 匹配 / 共 2000 条），超限截断并提示。
5. **文件后缀统计**：与代码根绑定的运行期内存缓存，由文件树加载/signature 变化时重算，不引入磁盘索引或独立 fs watcher。
6. **结果交互**：点击匹配行在右侧打开或激活文件 Tab 并滚到该行；搜索侧栏保持打开。

## 后果

- 搜索 UI 落在 `features/code`，共享布局仅扩展可选 slot，变更 Activity 不暴露入口。
- 新增工作区搜索 Tauri command 与 DTO，须同步契约文档。
- 大仓性能依赖有界结果与跳过二进制/超大文件，而非流式推送。

## 考虑过的替代方案

- Modal 宽 700px：与侧栏文件树割裂，用户明确改为 VS Code 侧栏模式。
- 调用系统 `rg`：速度好但环境不可控；双路径增加复杂度。
- 流式 event 推送：更「即时」但需取消、竞态与增量合并，首版不做。
- 独立 notify watcher 维护后缀索引：与现有 5s 文件树 signature 轮询重叠，首版不引入。
