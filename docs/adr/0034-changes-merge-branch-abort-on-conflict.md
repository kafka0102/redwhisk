# 0034. 变更 Activity 合并分支：合入当前分支，冲突则中止

## 状态

采纳（ticket 01 落地本地合并；远程点选由后续票完成）。

## 背景

变更 Activity 主 checkout「更多」需要在「创建分支」之后提供「合并分支」，交互对齐签出弹窗（本地 / 远程两段列表），功能对齐 VS Code「Merge Branch」（把所选分支合入当前分支）。RedWhisk 没有 VS Code 的 merge editor；若留下合并中状态，冲突文件会进入未提交变更，和「安全推送不污染工作区」（[ADR-0031](./0031-changes-safe-push-ff-only.md)）的产品取向冲突。

## 决定

1. **方向**：将选中的本地分支或远程跟踪引用合入当前分支；点远程引用时直接 `git merge <remote-tracking>`，不创建本地分支。
2. **历史**：沿用 git / VS Code 默认——可快进则快进，否则创建 merge commit；不强制 `--no-ff`，也不改成仅快进。
3. **列表**：弹窗列出全部本地与远程分支，只去掉当前分支；不过滤其他 worktree 占用分支或托管 Issue 工作分支。
4. **脏工作区**：有未提交改动则拒绝合并，提示先处理改动。
5. **冲突 / 失败**：`git merge --abort`（或等价回滚），工作区保持干净并报错；不把冲突文件留在未提交变更。不在本次加「中止合并」入口。

本决策不覆盖完成流程里的 `merge_branch_into_target`（`--no-ff` 对账合入）。

## 后果

- 用户可把 Issue / worktree 工作分支或 `origin/*` 合进主 checkout 当前分支，且不会被签出过滤规则挡住。
- 与 VS Code 的差异是：冲突不会进入可继续解决的合并中状态；用户需先在源分支或别处处理后再重试。
- 脏工作区必须先提交 / 丢弃 / stash（产品外）后才能合并。

## 考虑过的替代方案

| 方案 | 未采纳原因 |
| --- | --- |
| 留下合并中状态，冲突进未提交列表 | 无 merge editor，且会污染未提交变更 |
| 留下合并中状态并加「中止合并」 | 超出本次范围 |
| 始终 `--no-ff` | 与 VS Code / git 默认历史形态不一致 |
| 沿用签出弹窗过滤占用中分支 | 合并这些分支是主场景，不该隐藏 |
