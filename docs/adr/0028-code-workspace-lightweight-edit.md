# ADR 0028：代码工作区提供轻量文件可编辑态

## 状态

采纳（待执行）。

## 背景

「代码工作区」长期定位为浏览与只读查看。用户需要在应用内直接改少量文本并写回磁盘，但若把代码 Activity 做成完整 IDE（自动保存、诊断、多文件会话、重构），会显著抬高状态与交互复杂度，并与变更 Activity / Agent 工作流边界纠缠。

## 决定

1. 代码工作区文件**默认只读**；用户可按**文件 Tab**显式进入轻量可编辑态。
2. 落盘仅通过 **Cmd/Ctrl+S**；未保存改动用 Tab 关闭按钮左侧圆点提示。
3. 关 Tab / 退出可编辑 / 换根 / LRU 淘汰等会丢缓冲的路径，对 dirty 走三键确认（单文件：保存 / 不保存 / 取消；多 dirty：保存全部 / 全部不保存 / 取消）。
4. 外部磁盘签名变化：无 dirty 仍静默重载；有 dirty 时冲突提示（用磁盘版 / 保留本地版），不静默覆盖。
5. 明确**不是**完整 IDE：无自动保存、无诊断/重构、无跨根编辑缓冲；二进制与过大文件禁用编辑。

## 后果

- 需新增工作区写文件 Tauri command，与读文件共用路径校验。
- 文件 Tab 状态扩展 `isEditable` / dirty / 缓冲；外部刷新与 markdown 预览须与编辑态协作。
- 产品语言从「只读浏览」调整为「默认只读 + 轻量可编辑」。

## 考虑过的替代方案

- **始终可编辑 + 自动保存**：少确认、少 dirty，但易误改、难与外部刷新协同，偏离浏览优先。
- **完整 IDE 体验**：能力强但范围失控，超出本应用定位。
