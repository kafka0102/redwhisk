# 0025. TUI Issue 归档只保留用户输入与结论

**状态**：采纳  
**关联**：部分取代 ADR-0023 中「轻清理后保留命令输出与助手段落」的清理深度；ADR-0023 的纯文本形态、按 display_mode 分流、不迁历史仍有效。

## 背景

ADR-0023 将 TUI Issue 完成归档改为剥控制序列后的轻清理纯文本。实档（如 Codex TUI）仍大量混入 spinner/状态条粘连、工具过程回显与折叠行，回看难读；用户反馈过程细节不重要，核心是用户输入与每次输入前的结论。

## 决定

1. **写侧提取**（非展示侧补救）：`display_mode=tui` 完成归档时，在剥控制序列之后做**结论向提取**，仍写既有 archive 纯文本路径；不写 JSONL。
2. **保留集合**：真实用户输入块；以及每个用户 turn 之后、下一用户输入之前的**最后一段连续非过程正文**（结论）。首个用户输入之前的启动 banner / 上屏残留全部丢弃。
3. **丢弃集合**：TUI chrome（Working/spinner/状态头/装饰线等）、工具过程（如 `• Ran`、输出树、`… +N lines`）、中间思考与非最终助手叙述；不展开、不伪造被折叠全文。
4. **排版**：用户块与结论块之间、turn 之间各空 1 行；块内连续空行最多 1 行；不加 User/Assistant 标签或装饰分隔；UTF-8，文件末尾单个换行。
5. **适用范围**：所有 tui Session；**Codex 优先**加强识别，其它 provider best-effort。不迁存量归档。
6. **取舍**：宁可少留垃圾，不追求完整过程 transcript；启发式允许偶发切错。
7. **空结果回退**：当剥壳后找不到任何顶格真实用户 turn（Issue 初始 prompt 常被折叠为状态头，或 CSI 剥离后 `›` 粘在行中）时，**不得写空归档**；回退为轻清理纯文本（去 spinner/`Working` 状态行、压缩空行），保证完成态 session log 仍可回看。

## 后果

- 新完成的 TUI 归档显著变短、以结论为主；`latest_output` 取自提取后文本末行语义不变但内容更偏结论。
- 中途有用但非最终的说明会丢失——已接受。
- 测试以「用户输入 + 结论块 + 间距」与典型 Codex 噪声剔除为契约，不以 pixel-perfect 终端还原为契约。
- 无用户 turn 可识别时归档可能仍含过程噪声（轻清理级别），优先于空文件。
