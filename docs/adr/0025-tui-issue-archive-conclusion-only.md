# 0025. TUI Issue 归档只保留用户输入与结论

**状态**：采纳  
**关联**：部分取代 ADR-0023 中「轻清理后保留命令输出与助手段落」的清理深度；ADR-0023 的纯文本形态、按 display_mode 分流、不迁历史仍有效。

## 背景

ADR-0023 将 TUI Issue 完成归档改为剥控制序列后的轻清理纯文本。实档（Codex / Claude 等 TUI）仍大量混入 spinner、状态条粘连、thinking、工具过程回显与中间旁白，回看难读；用户反馈过程细节不重要，核心是用户输入与结论性输出。

既有实现曾以 Codex 标记（顶格 `›`、`• Ran`）为主；其它 provider（如 Claude Code 的 `❯` / `⏺` / `Thought for`）在无顶格用户 turn 时整段落进轻清理，归档仍巨噪。

## 决定

1. **写侧提取**（非展示侧补救）：`display_mode=tui` 完成归档时，在剥控制序列之后做**结论向提取**，仍写既有 archive 纯文本路径；不写 JSONL。
2. **保留集合**：真实用户输入块；以及每个用户 turn 之后、下一用户输入之前的**最后一段**以助手发言引导符开头的连续非过程正文（结论）。首个用户输入之前的启动 banner / 上屏残留全部丢弃。
3. **丢弃集合**：TUI chrome（Working/spinner/状态头/装饰线等）、工具过程（如 `• Ran`、`⏺Update(` / `Running`、输出树 `⎿`/`│`/`└`、`… +N lines`）、thinking / `Thought for` / Slithering / Brewed、中间旁白与非最终助手叙述；不展开、不伪造被折叠全文。
4. **多标记族**：纯文本启发式，**不传 `agent_type`**。用户 turn 前缀含 Codex `›` 与 Claude `❯`（拒绝残缺 prompt）；助手正文引导符含 `•` 与 `⏺`（非工具形态）。OpenCode/Grok 若撞上共用标记一并受益；无实档不强行特化。
5. **无用户 turn**：Issue 初始 prompt 常不在 terminal log 中。此时对**整段会话**做结论向提取，只留最后一段助手结论；**不以轻清理作为主路径**。
6. **三级回退**：① 有用户 turn → 每 turn 用户块 + 最后结论；② 无 turn → 全会话最后结论；③ 仍无助手正文 → **增强轻清理**（多标记族过程行删除 + 压空行）；仅原文为空才写空文件。
7. **排版**：用户块与结论块之间、turn 之间各空 1 行；块内连续空行最多 1 行；不加 User/Assistant 标签或装饰分隔；UTF-8，文件末尾单个换行。
8. **数据边界**：只读 terminal log；**不**从 Issue 描述/启动 prompt 伪造用户原文；**不迁**存量归档。
9. **取舍**：宁可少留垃圾，不追求完整过程 transcript；启发式允许偶发切错。

## 后果

- 新完成的 TUI 归档显著变短、以结论为主；`latest_output` 取自提取后文本末行语义不变但内容更偏结论。
- 中途有用但非最终的说明会丢失——已接受。
- 无用户 turn 时归档可能只有最后结论（用户原话仍在 Issue 详情）。
- 测试以「用户输入 + 结论块 + 间距」与 Codex/Claude 噪声剔除为契约，不以 pixel-perfect 终端还原为契约。
- 无助手正文可识别时归档可能仍含轻清理后的非过程残留，优先于空文件。
