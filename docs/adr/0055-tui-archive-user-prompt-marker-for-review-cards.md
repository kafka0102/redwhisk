# 0055. TUI 归档用逐行 › 标出用户块，供回看切卡

## 状态

采纳（待执行）。

## 背景

TUI 的 Issue Session 归档是一篇纯文本：用户输入和该轮结论只用空行隔开，没有角色标记（ADR-0025 第 7 条）。回看把整篇丢进同一块 Markdown，用户输入贴在左侧，和结论混在一起。json 回看则是用户卡与助手卡交替。

用户块和结论块内部都有空行。只在用户块第一行加 `›`、并在下一个空行结束用户卡，会把用户原文空行之后的内容画进结论卡。`archive-project-1-issue-320-session-370.log` 就是这种用户输入中间带空行的实档。

来源里的 Markdown 标题和段落空行在写盘时会被压掉或无法从旧纯文本恢复。json 的标题来自结构化消息正文里的 `#`，不是回看时补造的。

## 决定

1. **新归档的用户块**：每一行（含原文空行）都以 Codex 用户引导符 `›` 加一个空格开头；原文空行写成单独一行 `›`。结论块不加引导符。块间仍空一行。来源正文里的 `#` 标题和段落空行原样保留，不把连续空行压成一行。
2. **回看切卡**：只认新形态。连续的 `›` 行收成一张用户卡，并去掉引导符与其后一个空格；遇到不以 `›` 开头的行，其后整段直到下一个 `›` 行都是一张结论卡。用户卡用 json 用户气泡，结论卡用 json 助手气泡里的 Markdown。
3. **旧文件**：正文里没有这种逐行 `›` 时，维持现在这一篇 Markdown，不按空行猜测角色。不改写已落盘归档。
4. **范围**：本机会话记录路径与终端提取回退都按同一标记写。过程性工具输出、中间思考与 TUI chrome 仍不入档。

## 后果

- 新完成的 TUI 回看能把用户输入与结论分成交替卡片；结论里已有的标题和列表按 Markdown 显示。
- 旧归档观感不变。文件里本来没有的标题不会在回看时被造出来。
- 归档正文里会出现可见的 `›`。这是给回看切卡用的分界，不是再画一层终端 chrome。

## 考虑过的替代方案

| 方案 | 未采纳原因 |
| --- | --- |
| 只按空行奇偶切卡 | 用户块和结论块内部都有空行，分界与段落空行无法区分 |
| 只给用户块第一行加 `›`，用户卡到下一个空行结束 | 用户原文空行之后的内容会进入结论卡 |
| HTML 注释 `<!-- user -->` | 纯文本归档里多一种只有机器读的标记；`›` 已是现有用户引导符 |
| 回看时把每段首句提升成标题 | 会改写结论原文，和 json「渲染来源里的 Markdown」不一致 |
