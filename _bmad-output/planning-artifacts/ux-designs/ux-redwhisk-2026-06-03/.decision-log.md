# Decision Log：RedWhisk UX

本文件记录 UX 规格创建过程中的决策、假设和最终化动作。`DESIGN.md` 与 `EXPERIENCE.md` 是最终交付 spine；当 mock、导入素材或本日志与 spine 冲突时，以 spine 为准。

## 2026-06-03

### D-001：创建模式与输入

- **决策：** 使用 `bmad-ux` Create intent 创建 UX 工作区。
- **路径：** `_bmad-output/planning-artifacts/ux-designs/ux-redwhisk-2026-06-03/`
- **输入：** `_bmad-output/planning-artifacts/prds/prd-redwhisk-2026-06-03/prd.md` 与 `addendum.md`。
- **工作模式：** Fast path。
- **严谨度：** internal / developer tool。

### D-002：视觉参考与风格约束

- **Light 参考：** Multica 的白底、黑字、灰色辅助。
- **Dark 参考：** VS Code / Trae 的纯黑开发工作台。
- **风格目标：** 简洁、清新、克制、大气，有桌面软件质感。
- **避免：** 典型管理 SaaS、廉价网页应用、卡片堆叠、营销式 hero、彩色图表化看板、过度圆角、渐变装饰。

### D-003：UX 输出边界

- **决策：** 本次输出 `DESIGN.md` 与 `EXPERIENCE.md`，不生成 key-screen HTML mockups。
- **依据：** 用户没有要求视觉 mock；Fast path 可跳过 creative tools。当前目标是形成可交给设计和实现的 spine。
- **影响：** 关键屏幕以表格和行为规则表达；如后续需要可在 Update 模式中补 mockups。

### D-004：UI 系统假设

- **决策：** 假设前端使用 React + TypeScript + Tauri，并采用自建桌面工作台组件层，不以 shadcn / MUI 等 Web SaaS 组件库作为视觉基底。
- **依据：** PRD 已确定 React + Tauri；用户要求避免廉价网页应用和管理 SaaS 风格。
- **归档：** `EXPERIENCE.md` Foundation 与 `DESIGN.md` Brand & Style。

### D-005：主题策略

- **决策：** light 与 dark 都是一级主题；dark 不是简单反色，而是独立的开发工作台主题。
- **依据：** 用户明确要求支持 light 与 dark 两种风格。
- **归档：** `DESIGN.md` frontmatter colors 与 Colors 章节。

### D-006：Open items 处理

- **决策：** 快捷键、最小窗口宽度、`stopped` 状态命名和 key-screen mockups 作为非阻塞 open items。
- **依据：** 这些项目不会改变 MVP IA 和主流程，但需要 UX/实现阶段复核。
- **归档：** `EXPERIENCE.md` Open Items。

### D-007：对账与审查

- **决策：** PRD 对账和 UX 审查未发现阻塞项。
- **对账文件：** `reconcile-prd.md`
- **审查文件：** `review-ux.md`
- **残余风险：** 未生成 key-screen mockups；实现前建议补关键屏视觉参考。

### D-008：最终化

- **决策：** 将 `DESIGN.md` 与 `EXPERIENCE.md` frontmatter `status` 设置为 `final`。
